# カルラライブ 受付用デジタルチケット

配信をお任せいただく会に、追加料金なしでお付けする受付の道具です。申込の受付、当日の入場、終了後の報告までを扱います。
**チケットの販売と決済は扱いません。**

Cloudflare Workers（静的ファイル＋API）と D1 で動きます。見た目は `../design/karura-tokens.css`（ただ1つの元）を読みます。

## できること

| だれが | 画面 | できること |
| --- | --- | --- |
| 参加者 | `/join?e=会のID` | 申込。その場でチケットが出る。LINE連携を設定した会では「LINEで申し込む」も出る |
| 参加者 | `/t?k=チケットの鍵` | チケット。QRコードを見せる／タッチ（受付の4桁のコード）で入場／配信を見る |
| 参加者 | `/door?e=会のID&k=タグの鍵` | 受付に置いたタグ（NFC・掲示したQRコード）を読むと入場済みになる |
| 受付スタッフ・主催者 | `/staff?e=会のID&k=受付の鍵` | QRコードの読み取り、名簿からの入場、当日受付、CSVの取り込みと書き出し、4桁のコード、申込フォームの開け閉め |
| 受付スタッフ・主催者 | `/report?e=会のID&k=受付の鍵` | 開催報告（申込数、来場者数、入場の方法と時刻、オンライン視聴者数、LINEの友だち数）。印刷・PDF用 |
| カルラライブの担当者 | `/admin` | 会を作る、設定を変える、LINE連携、名簿の削除 |

### 入場の3つの方法

1. **QRコード**：参加者のチケットのQRコードを、受付のスマホ（`/staff` の「QRコードを読み取る」）で読む。いつでも使える
2. **タッチ（4桁のコード）**：参加者がチケットの「タッチで入場する」に、受付の4桁のコードを入れる。受付中だけ使える。5回まちがえると、そのチケットは受付での対応に切り替わる
3. **タッチ（受付のタグ）**：`/door` のURLを書き込んだNFCタグ、または掲示したQRコードを参加者が読む。チケットを開いたことのあるスマホなら入力なし、なければ申込のメールアドレスで入場。受付中だけ使える

紙の名簿は、`/staff` の「名簿をCSVで書き出す」から作ります。通信が不安定な会場では紙で受付し、あとで名簿から入場を記録します。

### あらかじめ決めていること（LPの記載と合わせています）

- 参加無料・招待制の会が対象。販売と決済はしない
- 会場の定員は、何も指定しなければ 300人
- 参加者の名簿は、会の終了から 30日で自動的に削除する（会ごとに変えられる）。削除のあとは、個人情報を含まない集計だけが残る
- LINE連携は有料オプション。主催者ごとに LINE 側の設定がいる

## 手元で動かす

    npm install
    cp .dev.vars.example .dev.vars     # 管理用の鍵など。コミットしない
    npm run db:migrate:local
    npm run dev                        # http://localhost:8791

`http://localhost:8791/admin` を開き、`.dev.vars` の `ADMIN_KEY` を入れて、会を作ります。

    npm test          # wrangler dev を立ち上げて、発行から入場、報告、削除までを通しで確かめる
    npm run typecheck

## 公開する

1. D1 を作る：`npx wrangler d1 create karura-ticket-db`。出てきた `database_id` を `wrangler.jsonc` に書く
2. 表を作る：`npm run db:migrate:remote`
3. 秘密の値を入れる
   - `npx wrangler secret put ADMIN_KEY`　　　管理画面の鍵。長いランダムな文字列にする
   - `npx wrangler secret put SESSION_SECRET`　LINE の申込の署名と、チャネルシークレットの暗号化に使う。途中で変えると、保存済みの LINE連携は設定し直しになる
   - `npx wrangler secret put RESEND_API_KEY`　任意。入れると、申込のときと `/staff` の「チケットをメールで送る」でメールを送る。入れなければメールは送らず、チケットのURLは名簿のCSVから主催者が送る
4. `wrangler.jsonc` の `vars` を確かめる：`MAIL_FROM`（差出人。Resend で認証済みのドメイン）、`LP_URL`
5. 公開する：`npm run deploy`
6. ドメインを当てる（例：`ticket.thisandthat.jp`）。LINE のコールバックURLはこのドメインで決まるので、LINE連携を使う前に決める

名簿の自動削除は、毎日 03:17（日本時間）に動きます（`wrangler.jsonc` の `triggers`）。

## LINE連携（オプション）を設定する

申込を LINEログインにして、同意のあとに主催者の LINE公式アカウントの友だち追加を出します（LINEログインの「友だち追加オプション」、`bot_prompt=aggressive`）。

主催者の LINE Developers コンソールで行うこと：

1. 主催者の LINE公式アカウント（Messaging API のチャネル）と**同じプロバイダー**に、LINEログインのチャネルを作る
2. LINEログインのチャネルに、LINE公式アカウントをリンクする
3. コールバックURLに `https://（このサービスのドメイン）/api/line/callback` を登録する（`/admin` の設定画面に表示されます）
4. チャネルを「公開」にする
5. チャネルIDとチャネルシークレットを、`/admin` の会の設定に入れる

受け取るのは LINE のユーザーIDと「友だちかどうか」だけです。メールアドレスは受け取りません。名前は申込フォームに書いたものを使い、LINE には送りません。

参考：<https://developers.line.biz/ja/docs/line-login/link-a-bot/>

## データの扱い

- 保存するもの：名前、メールアドレス、所属、参加の方法、入場の時刻と方法、配信を開いた時刻、（LINEで申し込んだ人だけ）LINEのユーザーIDと友だちの状態
- 削除：保存期間を過ぎると、名簿・チケット・LINE連携の設定を消し、集計（人数と時刻の分布）だけを残す。`/admin` から、待たずに消すこと、会ごと消すこともできる。1人だけ消すのは `/staff` の名簿から
- 鍵：受付スタッフ用のURL・タグ用のURL・チケットのURLには、それぞれ別の推測できない鍵が入る。受付スタッフ用のURLを知っている人は名簿を見られるので、渡す相手を絞る
- LINE のチャネルシークレットは、暗号化して保存し、画面にも API にも出さない
- 全ページ `noindex`。外部のスクリプトや計測は読み込まない
- 申込フォームは、URLを知っていれば誰でも申し込める。招待した人だけの会では、申込フォームは閉じたまま、名簿のCSVを取り込んで使う
